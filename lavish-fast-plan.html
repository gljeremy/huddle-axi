4 · One file that carries its context

Why this shape

  • It stays one portable file, which is what you like most about Lavish. The runtime is inlined, not loaded from a CDN.
  • The agent never writes CSS, JS or even HTML again. It reads and writes one card as a few lines of TOON; the CLI turns that into fixed-tag HTML.
  • Save writes the live state back into the file, TiddlyWiki-style, so a file you mail to someone carries the whole discussion.
  • The context block is the agent's memory. A fresh session reads that block instead of the chat transcript.
  • The facilitator is the only writer, so the file on disk always has exactly one author.
  • Card ids are stable, so threads, revisions and undo all hang off data-card.

4b · TOON on the wire, HTML on the page

The file keeps restricted HTML, so it still reads fine with JavaScript off. The agent never sees that HTML. Because the tag set is fixed, the CLI converts a card both ways with plain code, and the model only handles the compact form.

Agent sees and writes (TOON)

c2 decision
title: How do we collect setup data?
body: Three options on the table.
opts[3]: Long form up front,Progressive wizard,Import from CSV

About 150 characters. The same shape as the lists lavish-axi poll already prints, such as prompts[3]{uid,prompt,…}.

File stores (restricted HTML)

<section data-card="c2" data-kind="decision">
  <h4>How do we collect setup data?</h4>
  <p>Three options on the table.</p>
  <ul class="opts"><li>Long form up front</li>
    <li>Progressive wizard</li><li>Import from CSV</li></ul>
</section>

About 250 characters, written by the CLI, never by the model.

What it buys. Roughly 30–45% fewer output tokens per card, plus fewer ways to break the page: the model can't emit a stray tag or class. The prototype above counts both sizes on every agent patch.
Keep the gain in proportion. Card-scoped patching is the big win, cutting a round from ~15k tokens to ~300. TOON trims that ~300 to ~200, so it's worth having but secondary. Measure tokens and parse failures for both formats in step 2 before locking it in.

6 · Kun's lens on this plan

Receipts, not vibes. Measure stock Lavish first (comment → visible, split into agent time and reload time). The plan rests on the claim that agent regeneration dominates, so prove that before building anything.
Narrow prototype first. Build one board, one card swap and a fake agent before anything else. If card patching doesn't feel instant with a fake agent, nothing else will fix it.
Pick the model by task shape. A card rewrite is small and well defined, so a fast cheap model fits. Use a premium model only to create a board. Choose per task, not with a request router.
Deterministic where you can. Shorter, +Option, Split and Reorder are plain code, not LLM calls. Mix code, cheap judgment and occasional generation.
Agent ergonomics are the product. board patch c7 should give compact output and next-step hints, the AXI way. Don't make the agent re-read the board to edit one card.
Guardrails early. Cap files at about 1000 lines from day one, and make an end-to-end latency test (comment → visible < N s) the gate, not unit tests the agent wrote.

8 · Risks

Cross-card edits

"Make all options cheaper" touches 5 cards. Needs a multi-card patch, or fall back to a board rewrite.

Rigidity bites

A fixed card set can't express a one-off diagram. Allow a kind="html" card as the escape hatch, still edited one card at a time.

Overlapping patches

With one writer, the only race is you sending a second note on a card before the first patch lands. Queue patches per card.

Readable over screen share

Video calls blur small text and compress subtle colour. Cards need large type, and the "this changed" glow must be bold enough to survive compression.

Losing upstream

A fork misses Lavish's fixes. Keep the shared AXI pieces small enough to re-port.

Context bloat

The embedded threads grow forever. Compact old resolved threads into the brief.

TOON slips

Models have seen far less TOON than HTML. Commas inside text, or a wrong [n] count, will happen. A strict parser rejects the patch with a one-line error and the agent retries, and the old card stays on screen meanwhile.

Escape-hatch cards

A kind="html" card has no TOON shape. It travels as raw HTML in one field, so it costs more and that's acceptable for rare cards.
